# 좌우 카메라로 경로 재현하기

`replay_stereo_route.sh`는 주행 기록에 저장된 좌우 사진, 전진·회전 순서와 시간을 읽습니다.
주행 중 촬영한 사진과 모터 상태도 새 폴더에 저장합니다.

- 경로 위치를 확인할 수 있으면 다음 구간의 방향과 전진 시간을 보정합니다.
- 현재 사진에서 위치를 찾기 어려우면 정면 거리 검사에 통과하는 동안 기록된 동작을 이어갑니다.
- 정면 가림판이나 장애물 후보가 약 45 cm 안에 들어오거나, 좌우 영상의 거리 근거가 부족해지면 멈춥니다. 새 프레임 두 장에서 정면이 다시 확인되면 이어갑니다. 거리 판단이 약 4초간 돌아오지 않으면 종료합니다.
- 이 검사는 현재 영상에서 구하며, 지도 위치나 `/partition/wall_scan` 발행 여부와 독립적입니다. 카메라 시야 밖과 좌우·후방은 이 검사 범위에 포함되지 않습니다. 바닥 반사와 가림 때문에 멈출 수 있습니다.
- 경로 후반에 양쪽 카메라에서 ID 22를 찾으면 마커의 거리와 방향으로 접근합니다. 카메라에서 58 cm 이내이고 방향 차이가 5° 이하인 관측이 연속 두 번 들어오면 종료합니다.

## 실행

노트북에서 프로젝트 폴더를 열고 `offline-replay-validation.json`의 전체 경로를 아래 `report`에 넣습니다.
기존 카메라 스트리밍과 Nano의 SSH ControlMaster 연결을 사용합니다.
다른 키보드 주행이나 자율 주행 프로그램을 종료한 상태에서 시험하세요.

```bash
report="/경로/offline-replay-validation.json"
bash replay_stereo_route.sh "$report" --offline
bash replay_stereo_route.sh "$report" --inspect
bash replay_stereo_route.sh "$report"
```

`--offline`은 저장 사진의 거리 판단을 검사합니다. `--inspect`는 로봇의 현재 영상과 모터 상태를 읽습니다.
옵션을 생략하면 출발 영상 일치와 거리 근거까지 확인하며, 위 세 명령은 모두 모터를 활성화하지 않습니다.

실제 시험은 기록을 시작한 위치·방향에 로봇을 놓고 주행 통로를 비운 상태에서 실행합니다.

```bash
bash replay_stereo_route.sh "$report" --execute
```

`Ctrl+C`로 정지할 수 있습니다. Nano의 명령 타임아웃도 연결이나 처리 중단에 대비합니다.
출력의 `stop_confirmed`로 최종 모터 정지 여부를 확인합니다.

## Nano 안에서 실행하기

`nano_replay.sh`는 같은 경로 재현기를 Nano의 ROS 2 컨테이너 안에서 실행합니다.
카메라 검사와 모터 명령 생성은 Nano 안에서 이루어지며, SSH는 시작·정지·상태 조회에 사용합니다.
카메라 또는 내부 제어가 멈추면 드라이버 명령 타임아웃이 적용됩니다.

처음 배치할 때는 기존 `offline-replay-validation.json` 경로와 호환 ARM64 OpenCV 휠을 전달합니다.
OpenCV를 배치한 뒤 코드나 보정 파일만 갱신할 때는 휠을 생략할 수 있습니다.

```bash
bash nano_replay.sh deploy "$report" "$opencv_arm64_wheel"
bash nano_replay.sh test
bash nano_replay.sh status
```

`test`는 Nano에서 현재 영상을 읽고 마커 위치를 계산하며 모터를 활성화하지 않습니다.
`motion-test`는 등록된 마커와 가까운 정면 공간을 확인하고 최대 0.24초 전진한 뒤 정지합니다.
`probe`는 기록된 출발점과 현재 영상이 일치하는지도 정지 상태에서 검사합니다.
실제 재현 시험에서는 출발점에서 `start`를 실행하고 `status`로 결과를 확인합니다.
`start 25`는 같은 경로의 중간부터 25번 마커를 탐색하고, 확인하면 그 마커에 접근합니다.
`stop`은 Nano 프로세스에 모터 정지와 비활성화를 요청합니다.

등록된 마커가 연속 두 프레임에 보이면 잠시 멈춥니다.
PWM이 0으로 유지된 동안 왼쪽 카메라 영상에서 위치와 방향을 계산하고 `pose_estimated`로 기록합니다.
ID 24와 25는 그림에서 읽은 임시 좌표를 사용합니다.
마커로 계산한 위치는 현재 버전의 주행 기록에 남습니다. 경로는 기존 기록을 기준으로 재현됩니다.

## 추가 ArUco 표식 두 장

[인쇄용 PDF](../assets/aruco-4x4-50-id24-id25-150mm-a4.pdf)의 1쪽은 ID 24, 2쪽은 ID 25입니다.
A4에서 **실제 크기 100%**로 출력하고 자로 검은 외곽 한 변이 150 mm인지 확인합니다.
필요하면 종이 바깥을 잘라내되 검은 테두리 둘레의 흰 여백을 유지합니다.

- **ID 24**는 긴 직선 통로를 달릴 때 정면에 보이는 끝 가림판 안쪽 면에 붙입니다.
- **ID 25**는 그 모서리를 우회전하고 나서 정면에 보이는 아래쪽 통로 끝 가림판 안쪽 면에 붙입니다. 주행 기록에서 손글씨가 보였던 패널입니다.

두 표식 모두 검은 사각형 중앙이 바닥에서 약 10 cm 높이가 되게 평평하게 붙입니다. 카메라에서 종이가 반사되거나 가려지지 않아야 합니다.
재현 코드는 ID 24와 25를 발견하면 거리와 방향을 기록합니다. 인쇄물의 지도 좌표를 확정한 뒤에는 기존 `scripts/aruco_initial_pose.py --marker-id 24 --marker-mm 150 --anchor <파일>`처럼 위치를 추정할 수 있습니다.
지도 기준 파일에는 `x_m`, `y_m`, `normal_yaw_deg`를 넣습니다. 앞의 두 값은 검은 정사각형 중심 좌표이며 마지막 값은 마커 면에서 카메라 쪽으로 향하는 방향입니다. ID 25도 같은 방식으로 등록합니다.
